# German Werks - Operator Guide

Storefront for German Werks. **Payload CMS 3 + Next.js 15** in one app: storefront, admin at `/admin`, REST at `/api`. MongoDB for data, Stripe Checkout for payment. CAD only, shipping to Canada only.

## Layout

- `app/(frontend)` storefront, `app/(payload)` admin and API (generated by Payload, do not edit)
- `cms/` Payload config, collections, globals, seed
- `lib/commerce/` storefront data layer (products, cart, checkout, fulfilment)
- `scripts/stripe-tax-rates.ts` creates the Canadian tax rates in Stripe; `lib/commerce/provinces.ts` holds the province list and percentages

Payload coding rules are in `AGENTS.md` (shared with UEForged). Its examples use `src/`; here Payload code lives in `cms/`.

## Local dev

```bash
pnpm install
cp .env.example .env        # DATABASE_URL points at local mongod, database `germanwerks`
pnpm seed                   # collections, products, pages, menus, shipping options
pnpm dev                    # http://localhost:3000, set PORT or `-p` for another port
```

Set `PAYLOAD_PUBLIC_SERVER_URL` to the URL you are serving from. Create the first admin at `/admin`, or run seed with `SEED_ADMIN_EMAIL` and `SEED_ADMIN_PASSWORD`.
After changing collections or globals: `pnpm generate:types` and `pnpm generate:importmap`.
Tests: `pnpm test` (uses the throwaway database `germanwerks_test` on local mongod).

## Content

Everything is edited in `/admin`: Products (variants, prices in cents, stock), Collections, Pages, Media, and the globals Site Settings (navbar/footer menus, contact email that receives order notifications) and Shipping Settings (flat-rate options offered at checkout). A product is sellable while any variant has stock; stock is decremented when an order is paid.

## Updating content programmatically (REST API)

Use this for bulk work (e.g. a spreadsheet of products). Everyday edits are easier in `/admin`. Auth is a Payload API key:

1. In `/admin`, open your user, check **Enable API Key**, copy the key.
2. Send it on every request: `Authorization: users API-Key <key>`

Upload the image first, then reference its id:

```bash
curl -s -X POST "$SITE/api/media" \
  -H "Authorization: users API-Key $KEY" \
  -F file=@hood.jpg \
  -F '_payload={"alt":"Dry carbon hood, three-quarter view"}'
# response contains doc.id

curl -s -X POST "$SITE/api/products" \
  -H "Authorization: users API-Key $KEY" \
  -H "Content-Type: application/json" \
  -d '{"title":"Dry Carbon Hood","collections":["<collection-id>"],
       "images":[{"image":"<media-id>"}],
       "options":[{"name":"Finish","values":["Gloss","Matte"]}],
       "variants":[
         {"title":"Gloss","selectedOptions":[{"name":"Finish","value":"Gloss"}],"priceCents":249900,"sku":"GW-HOOD-G","stock":3},
         {"title":"Matte","selectedOptions":[{"name":"Finish","value":"Matte"}],"priceCents":259900,"sku":"GW-HOOD-M","stock":2}]}'
```

- **products**: `title`*, `handle` (generated from title when empty), `description` (rich text, easiest in admin), `images: [{image}]`, `tags`, `featured`, `collections` (ids, `GET /api/collections`), `seo {title, description}`, `options`, `variants`* (`priceCents` is CAD cents: $2,499.00 = 249900; `stock` required). `availableForSale`, `minPriceCents`, `maxPriceCents` are derived; don't send them.
- **collections**: `title`*, `handle`, `description`, `image`
- **globals**: `/api/globals/site-settings` (menus, contact email), `/api/globals/shipping-settings` (flat-rate options)
- Orders are created only by Stripe checkout; never create them by hand.

## Orders

Paid orders appear in `/admin` under Orders. Set status to `shipped` and add a tracking number: this stamps `shippedAt` and emails the customer once. Refunds are issued in the Stripe dashboard only.

## Stripe setup

1. Put `STRIPE_SECRET_KEY` in `.env` (use test keys first).
2. Create the 13 province/territory tax rates (idempotent, safe to re-run):
   ```bash
   pnpm stripe:tax-rates
   ```
   Rates are combined GST/HST/PST per province, tagged in Stripe with metadata `germanwerks_province`, which is how checkout finds them (no env var). To change a rate, edit `lib/commerce/provinces.ts` and re-run the script: it archives the old rate and creates the new one.

   How tax works: the customer picks their province in the cart, and that province's rate is charged on the products (not on shipping). Stripe cannot apply Canadian rates from the shipping address (`dynamic_tax_rates` is deprecated and never supported Canada), so after payment the order records `taxProvince` and sets `taxMismatch` when the shipping address is in a different province. Mismatched orders show in the Orders list; the owner decides whether to refund the difference or ask for the rest.
3. Dashboard, Developers, Webhooks, add endpoint `https://germanwerks.ca/stripe/webhook` with event `checkout.session.completed`. Copy the signing secret into `STRIPE_WEBHOOK_SECRET`.
4. Local webhook testing: `stripe listen --forward-to localhost:3000/stripe/webhook`, use the printed `whsec_` as `STRIPE_WEBHOOK_SECRET`.

Fulfilment is idempotent and runs from both the webhook and the `/order/{session}` page the customer lands on, so a missed webhook does not lose an order.

- Env: `/var/www/germanwerks/.env`, never committed

First-time setup on the droplet:

```bash
git clone https://github.com/jaskirat-gill/German-Werks.git /var/www/germanwerks && cd /var/www/germanwerks
cp .env.example .env && nano .env
pnpm install --frozen-lockfile && pnpm seed   # fresh database only; delete the sample products in /admin before launch, keep the menus and shipping options
pm2 start ecosystem.config.cjs && pm2 save
```

Nginx server block `/etc/nginx/sites-available/germanwerks`, then symlink into `sites-enabled` and `certbot --nginx -d germanwerks.ca -d www.germanwerks.ca`:

```nginx
server {
    server_name germanwerks.ca www.germanwerks.ca;
    client_max_body_size 25M;
    location / {
        proxy_pass http://127.0.0.1:3001;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

Keep `client_max_body_size` (admin uploads break without it). The Stripe webhook needs the raw body, so no Nginx rewriting on `/stripe/webhook`.

## Deploying

The droplet is small, so build locally and ship the build:

```bash
pnpm build && rsync -az --delete .next/ root@129.212.166.116:/var/www/germanwerks/.next/
ssh root@129.212.166.116 'SKIP_BUILD=1 bash /var/www/germanwerks/deploy.sh'
```

`deploy.sh` alone does `git pull`, `pnpm install`, `pnpm build`, then restarts PM2. Content changes need no deploy.

## Cautions

- Never delete `/var/www/germanwerks/media` or reclone over it.
- Do not run `pnpm seed` against a database with real products (it skips when products exist, but check first).
- Do not run `pm2 restart all` or touch `ue-forged`; they share the droplet.
